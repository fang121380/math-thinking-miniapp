# 微信代码质量体积修复（2026-09-20）

## 问题与口径

微信开发者工具代码质量面板显示两项未通过：主包超过 1.5 MiB，图片和音频资源总量超过 200 KiB。检查当前 Stable 2.02.2608070 内置质量检查器后确认：

- `PACKAGE_SIZE_LIMIT` 按编译后每个包分别统计，阈值为 1.5 MiB。
- `IMAGE_AND_AUDIO_LIMIT` 对整个编译结果内的图片、SVG、音频和视频求和，阈值为 200 KiB；把音频移到分包不能规避该项。
- 原自动测试只限制主包小于 1.75 MiB、媒体小于 1.3 MiB，门槛与开发者工具不一致。

## 修复

- 保留全部 10 首可选古典背景音乐及原有切歌入口，改用已配置下载域名 `upload.wikimedia.org` 的 HTTPS MP3 转码。
- 删除安装包内 10 个重复的背景音乐 MP3；点击、导航、答题正误和完成等低延迟短音效继续离线打包。
- 更新素材来源与许可记录。前三首改用 Wikimedia Commons 上的 CC0/PDM 录音，其余曲目继续使用已记录的 CC0/PDM 来源。
- 自动测试改为微信开发者工具相同的 1.5 MiB / 200 KiB 门槛和媒体扩展名集合，并约束背景音乐只能指向许可域名的 HTTPS MP3。

## 验证

- `npm run prepare:upload` 通过：21,297 道题审计 0 错误，455 项测试通过。
- 源码口径主包 886,133 bytes，全部媒体 169,154 bytes。
- 开发者工具 CLI 预览包成功：总包 729,510 bytes，主包 682,517 bytes，初中分包 46,993 bytes。
- 微信模拟器通过 `wx.createInnerAudioContext` 检查 10 首远程曲目，全部触发 `onCanplay`，未出现格式或地址错误。
- 实现提交 `6c3b9d4` 已推送；GitHub Actions Verify 运行 `35488581806` 通过。
