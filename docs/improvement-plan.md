# 梵数学改进计划

## 第一批：工程基础和已复现缺陷

- 将展开后的源码、测试、题库审计和 GitHub Actions 工作流纳入版本管理。
- 统一本地与 CI 的 Node.js 24 环境及 `prepare:upload` 检查入口。
- 使用公共配置模板和可重复执行的初始化命令，保留本机 AppID。
- 修复掌握度 0 被当成默认值 50 的选题错误，增加行为回归测试。
- 每批完成后先测试、审计，再提交；本地提交不等于已推送或云端 CI 已通过。

## 完成后的 GitHub 同步要求

用户要求：**全部做完并测试通过后，必须同步到 GitHub，不能只留在本地。**

- 每批改动通过验证后及时 commit；全部约定工作完成后，对最终代码执行 `npm run prepare:upload` 和适用的运行验证。
- 同步目标为 [fang121380/math-thinking-miniapp](https://github.com/fang121380/math-thinking-miniapp) 的对应开发分支。同步前核对远程历史，保留既有提交，正常 push，不以覆盖远程历史的方式处理差异。
- 推送后确认远程分支包含本地提交，并检查 GitHub Actions。失败时修复并重新测试、提交和同步。
- 完成汇报中列出测试结果、commit、GitHub 分支链接和 CI 状态；未验证的真机项目与同步阻塞必须如实列出。
- 该同步已获用户授权，无需在正常收尾时重复询问是否推送。若缺少提交身份或仓库访问权限，应明确说明尚未同步及所缺信息。

## 后续批次与验收依据

1. **教材校准**：先以默认人教版四年级为试点，核对有明确年份的教材目录、上下册与知识点映射。保留逐项来源和未覆盖项，不把自动检查标为人工教研结论。
2. **题库教研**：明确模板族、变式、审核状态和实际审核记录；为代表题准备人工复核清单。题量、去重数量与教学有效性分别报告。
3. **自适应策略**：在现有难度选择契约上设计可解释的难度调整，覆盖连续错误、提示依赖、冷启动和知识点隔离。先做离线回放，教学效果另由真实试用验证。
4. **数据可靠性**：先设计可导出、可校验、可恢复的本地备份；多孩子档案与云同步需要另行确定账号、后端和冲突处理方案。
5. **内容更新**：确定远程内容数据格式、校验与兼容规则、原子切换和失败回退，再接入实际发布端点。当前仅有更新通知预留接口。
6. **运行验证**：在微信开发者工具和真机验证诊断、练习、错题补救、游戏、音频、返回路径、包体积与加载表现；记录设备和结果。

当前自动测试和审计不替代教材人工审核、学生试用或真机验收。
